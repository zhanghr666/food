# 食物管家

Android 本地食物管理应用。语音、照片识物、包装文字和 SQLite 库存都在本机处理，识别模型随安装包提供，不使用业务服务端，不加入条码扫码。

## 录入流程

1. 语音、拍照、文字或直接填写。常用食品可以复用名称、分类、单位和位置。
2. 在同一表单核对六项核心信息：名称、数量、单位、存放位置、到期 / 计划食用日期、食物大类。填写前后保持同一布局。
3. 在表单卡片底部保存。可选信息、记住常用信息与保存集中排列，“再加一件”与保存并排。每次智能识别只整理一种食物；其他食物由用户主动点击“再加一件”，不会自动追加。多件草稿可在上方删除当前项，保留其余内容。

上述三个步骤指三个操作阶段，不表示任意信息缺失时只需点击三次。六项核心信息保存时检查完整性；其他信息展开即可填写，无非空要求。入库日期默认今天，生产日期、品牌、规格、单价和备注默认留空。

每个核心字段展示来源：语音识别、文字解析、照片识别、推算 / 建议、常用信息或手动填写。页面显示填写进度和待确认项，不用填入项数冒充识别正确率。歧义名称在名称输入框旁显示候选，点选后同步更新分类；人工修改不会被再次识别覆盖。键盘显示时隐藏底部导航，表单和保存操作一起滚动，不保留独立保存栏。

原文框右下方提供清空入口。成功识别后，原文未修改时只显示“上述文字可以编辑后重新识别”；修改后出现“按修改后的文字重新识别”，点击会重新调用本机解析并更新新文字提供的自动字段，不再只补空白。手动字段仍受保护，补充句保留未涉及的信息，成功后提示恢复，失败可重试。

日期使用年、月、日三列滚动选择，打开到期日期面板即可选择跨月、跨年的日期，并显示完整日期与距今天的天数。月、日循环滚动，月末或闰年变化自动调整为有效日期；保留快捷日期及生产日期加保质期的计算方式。生产日期和入库日期共用同一控件，历史日期仍可录入。

语音保留多条转写假设，按名称、数量、单位、地点和日期比较差异，不按“填写得多”选定正确结果。建议可逐字段修改或确认；若认可当前填写值，点击保存后在弹窗中一次确认即可入库，不必逐项点选。弹窗列出各食物待确认字段的当前值，日期展示用途与完整日期；缺失或格式错误仍须补齐。取消保留草稿，内容改变后须重新确认。提醒与字段关联，修改对应字段后不继续显示旧问题；语音、包装文字和照片数量共用该提醒状态。

语音按住说话、松开结束并整理，移出按钮取消。首次允许麦克风后重新按住，进入语音页提前预热离线模型。无障碍服务可分别触发开始、结束操作。

语音倒计时遇到疑似单位错字时按语境提出日期建议，例如“还有三千过期”可能表示“还有三天过期”。仅明确的到期倒计时启用，保留数值及原始转写，推断日期需要确认；真正的千克、千份及完整时长不作全局替换。文字手填和 OCR 不启用该语音纠错。

名称同音候选同时支持数量在前和在后。“个人”紧邻已知食品名称时可提出待确认量词建议，优先常用食品单位，再使用适合该食品的常见单位；不会把整段原文中的“个人”全局改成“根”。名称、单位和日期分别核对，也可在保存时确认当前建议值。

位置使用可直接编辑的输入框，识别出的地点可就地修改；下方保留常用位置标签，点选填入后仍可补充详细方位。自由填写不需要先在设置里建立位置，也不会自动新增常用标签。“放在储藏室”可单独补充当前食品，“客厅柜子里”“办公室抽屉”等完整地点不会被常用位置的短名称截断；完全匹配的自定义别名仍可映射为正式名称。

识别完成后，录入方式和原文输入区保持展开，滑动即可修改原文或食品字段，不再收起为“再次识别”入口。点击按原文整理时收起键盘，便于核对下方结果。

## 本地识别范围

语音使用内置模型的通用离线听写，不再设置应用限制词表，也不从常用食品或位置生成听写语法。模型自身的词汇和识别能力仍有边界，多条转写保留用于核对。听写后的文字名称和包装分类继续使用食品词典，覆盖凉粉、凉皮、肠粉、米线、糍粑等地方食品。词库外名称先按数量、地点、日期及状态的边界提取，避免逐字删除量词而截坏“自制粉条”“千层酥”等名称；备注或日期补充句不会被当作新食品。未说出的数量和单位仍留空，分类来源标记为推算 / 建议。

- Vosk 内置中文语音模型，将语音转为文字，再使用结构化解析提取字段。
- EfficientDet Lite0 int8 识别模型支持苹果、香蕉、橙子、西兰花、胡萝卜、三明治、热狗、披萨、甜甜圈和蛋糕。其他食品使用包装文字或手动补填。
- ML Kit 内置中文 OCR 同时读取整张包装文字，保留空间位置辅助配对日期标签。孤立日期只显示候选，需确认用途；生产日期和保质期均明确时才推算到期日。
- 拍照数量仅为可见物体的建议，不代表完整库存数量。无法从照片确定的存放位置、批次到期日不会凭空生成。
- 正确识别至少四项是效果验收目标，真实语音及包装照片测试完成之前不宣称已达标。

## 新版结构

- `core/EntryDraft.kt`：六字段证据、人工保护、合并和校验。
- `recognition/`：文字结构化解析及整图识物。
- `ui/entry/`：独立录入状态与确认页。
- `ui/InventoryViewModel.kt`、`ui/PantryApp.kt`：库存、位置、设置与导航。
- Room 新数据库 `food_manager_next.db`，结构版本 1，无旧版迁移。
- 应用名称保持“食物管家”，恢复原标识 `com.example.foodmanager`；验证包为 `com.example.foodmanager.validation`，仅用于隔离测试。
- 包装到期与个人食用计划使用不同的通知渠道。

保存成功后清空草稿，失败保留。人工修改的核心字段不会被重新识别覆盖；同一草稿重试使用唯一标识防止重复入库。切换页面和配置重建保留草稿。

## 构建与验证

使用项目 Gradle Wrapper、Android SDK 37 和仓库配置的 Java 工具链。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
.\gradlew.bat :app:assembleValidation :app:assembleValidationAndroidTest -PtestBuildType=validation
```

连接已允许 USB 调试的 ARM 手机后，针对新版测试运行：

```powershell
.\gradlew.bat :app:connectedValidationAndroidTest -PtestBuildType=validation "-Pandroid.testInstrumentationRunnerArguments.class=com.example.foodmanager.NewAppInstrumentedTest,com.example.foodmanager.EntryStateInstrumentedTest"
```

测试源码只保留在本地，按用户要求不纳入 Git。旧版回归辅助类仍供已有测试使用，但旧录入和首页页面已移除，新应用只使用新的导航与录入状态。
