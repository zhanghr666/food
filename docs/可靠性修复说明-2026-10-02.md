**可靠性修复说明 · 2026-10-02**

本次针对综合评估中的页面状态、保存确认、时间刷新、数据库升级和权限承诺实施修复，保留现有产品结构与位置留空规则。

**页面与保存**

- 页面恢复使用带类型的编码，新增记录不再与归档页共用标识。
- 编辑页由一个 EditorViewModel 持有内容，加载、手工修改、识别填充和保存校验读取同一份数据；每次重新进入新增页启动新会话。
- 编辑内容写入 SavedStateHandle；录入页的手工内容和识别草稿注册状态快照，草稿恢复时推进 id 计数器，避免新草稿撞号。
- 保存中防重复提交，成功写库后才清空或退出；写入失败保留内容并显示重试提示。异步提交使用快照，批量成功只移除已提交条目。
- 返回时对未保存修改给出确认；通知跳转也不会直接丢弃正在编辑的内容。已用完和清空草稿增加确认。
- 图片与相册共用解析参数和用户食品词表；相册图像在后台处理并释放位图。拍照等待结果的文件路径纳入状态恢复。

**时间与通知**

- 统一的日期 Flow 参与统计、提醒和排序；前台监听日期、时间、时区、分钟广播，返回前台立即更新。
- 首页和库存读取相同日期；关闭横幅不再错误显示“没有临期或过期食物”。
- 按自然日计算剩余天数，修复跨夏令时时用 24 小时相除造成的误差；历史日期仍以本地零点时间戳存储，未做日期字段格式迁移。
- 通知导航按生命周期收集 StateFlow；某一类别清空后取消该类旧通知，删除/归档触发检查，关闭提醒同时清理现有通知。
- 提醒时间明确为“约在此时检查”，设置显示系统实际授权/通知渠道状态并提供开启入口。

**升级与权限**

- v1–v7 直接迁移到 v8：检查实际列、迁移常用项、复制重建设置表，不再尝试 DROP COLUMN 后忽略异常。
- 保留旧数据和设置；旧自定义列表存在但为空时，不补回默认项。数据库迁移发生异常时由 Room 事务回滚。
- Manifest 显式移除依赖传递引入的 INTERNET；保留不提供联网能力的 ACCESS_NETWORK_STATE，以支持 WorkManager 系统状态检测。
- 启动时不再索取录音与通知权限；语音页面申请录音，实际打开录音设备前再次校验，权限撤销有错误反馈。
- 系统云备份关闭。Android 12+ 仅允许系统设备间迁移食物数据库及其 WAL/SHM；旧系统自动备份内容全部排除。设置页明确提示此策略及卸载后的恢复限制。
- 移除不受支持的 Kotlin source-charset 参数；保留 UTF-8 构建配置与中文编码测试。

**验证方式**

构建产物分为正常 Debug 包和独立 validation 包。设备测试只安装 `com.example.foodmanager.validation` 与其测试包，不升级、不读取现有 `com.example.foodmanager` 用户数据。测试数据库采用内存库或 `migration-test-*` 文件。

单元测试覆盖既有解析、输入清洗与编码，加上导航编码、草稿序列化恢复和夏令时自然日计算。设备测试使用真实 Room/SQLite：v1–v7 共 14 种有常用位置/已删空位置场景、无写库跨天刷新、保存失败保留、重复提交、新编辑会话、SavedState 恢复、最终安装包权限及无网络权限 OCR。页面测试另行验证 Activity 重建与返回确认。

SQLite 写入失败通过测试库的 `RAISE(ABORT, ...)` 触发器注入；没有通过破坏设备存储或用户数据库模拟故障。

复现构建与测试包：

```powershell
.\gradlew.bat :app:testValidationUnitTest :app:assembleDebug :app:assembleValidation :app:assembleValidationAndroidTest :app:lintDebug :app:processReleaseMainManifest '-PtestBuildType=validation'
```

设备若禁止安装时自动授予权限，可手动安装 validation 的两个 APK（不加 `-g`），再运行：

```text
adb shell am instrument -w -r -e class com.example.foodmanager.ReliabilityInstrumentedTest,com.example.foodmanager.PageRecoveryInstrumentedTest com.example.foodmanager.validation.test/androidx.test.runner.AndroidJUnitRunner
```
