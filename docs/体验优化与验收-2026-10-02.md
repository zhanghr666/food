# 食物管家体验优化与验收说明

日期：2026-10-02。范围：用户选定的 1、2、3、4、5、8、9、11 项。保留原有离线定位与技术架构。

## 已实施

| 项目 | 现在的行为 |
|---|---|
| 1 状态文案 | “新鲜”改为“未临期”，“无保质期”改为“未设置到期日”；说明状态仅依据已填写日期，未设置日期不触发提醒 |
| 2 可读性 | 状态色随浅深主题变化，临期使用较深琥珀色；辅助标签提升至 14sp；名称允许两行，色条随内容高度伸展，修正嵌套页面重复占用顶部空间 |
| 3 数量 | 可直接修改小数余量；留空表示未知，明确输入 0 表示剩余为零；保存成功后才提示，失败保留输入；归零时可选择归档 |
| 4 识别核对 | 移除未经校准的“置信度百分比”，展示待补充字段与日期来源说明；提示对照包装核对生产日期/到期日；未识别数量不再把默认 1 展示为识别事实 |
| 8 库存操作 | 卡片保留修改余量、编辑、更多；归档与永久删除移入更多菜单；归档成功后提供撤销，永久删除仍需确认 |
| 9 首页 | 待处理食品置顶，先展示三条并保留全部入口；统计改为两列，点击状态进入对应库存筛选，可在库存清除筛选 |
| 11 设置 | 解析条数、识别模式等信息移入默认折叠的“帮助与诊断”；数据与隐私保留记录统计、归档及清空入口 |
| 5 验收 | 增补历史库、数量语义、页面重建、返回确认、通知意图跳转、归档撤销、筛选及深色大字体测试 |

## 数据兼容

数据库升到 v9，新增 quantitySpecified 字段。旧正数量标为已填写，旧零数量保留为未填写；旧数据无法可靠判断“0”当时代表用完还是未知，因此不擅自归档。明确的零数量与未知数量从本版本开始区分。

迁移保留原记录与设置：v1–v7 先执行已修复的兼容迁移至 v8，再升级到 v9；v8 只补充数量标记。新增 v9 schema 已导出。

## 验证记录

- 64 项 JVM 单元测试通过，0 失败。
- Debug 与独立 validation APK 构建成功；Lint 0 错误、25 条警告。
- Android 16 真机的一轮完整测试：13 项全部通过，涵盖 3 项页面测试与 10 项数据/可靠性测试。
- 迁移用例覆盖 v1–v8 的 16 个夹具场景，并检查记录、数量标记、设置及常用位置。v4–v6 缺少仓库原始 schema，按历史代码构造，不等同于所有真实用户旧库抽样验证。
- 页面测试：余量归零→归档→撤销；首页状态筛选与清除；Activity 重建保留编辑内容；系统返回确认；冷启动携带提醒意图及已有 Activity 收到提醒意图时保护未保存编辑。
- 已查看首页、库存和 1.4 倍字体的深色卡片截图。大字体检查只覆盖该卡片，不代表全部页面的无障碍认证。
- 设备测试启动曾停在前台 Activity 启动阶段；通过在独立测试包上显式启动 Activity 后完成。保留原始失败日志，不把测试工具的生命周期失败作为产品崩溃结论。

最终验收补记：用户允许小米系统的启动确认后，独立 validation 包再次完整执行 13 项设备测试，全部通过。原始结果：`app/build/reports/usability-accepted-device-tests.txt`。测试过程中仍需在测试切换 Activity 时显式将测试应用带到前台，尚不能宣称该机型无人干预执行稳定。早前出现的 No compose hierarchies / 页面等待超时等失败日志保留在 build/reports 中。

状态标签颜色按前景色与其 14% 透明容器在对应 surface 上合成后的 sRGB 对比度计算：浅色四种状态约为 5.07、5.84、5.04、7.29；深色约为 8.21、8.60、8.31、8.20。此计算针对标签，不代表整款应用已完成无障碍认证。

## 尚需不同环境验收

- Android 7 等旧系统实体设备，以及不同厂商的省电、锁屏、重启后的后台提醒时序。
- 当前手机不允许测试工具授予通知权限；已覆盖拒绝授权路径、空列表清理和通知跳转逻辑，尚未验证系统通知实际送达及逐渠道关闭后的完整用户操作。
- Activity 重建和状态序列化测试不等于真实系统杀进程全流程，更不承诺强制停止、断电或卸载后保留草稿。
- 系统换机迁移需要两台设备验证。

## 复现

构建时使用 `--no-parallel --max-workers=1`，避免多个变体首次同时导出同一 Room schema 造成写入竞争。

```powershell
.\gradlew.bat :app:testValidationUnitTest :app:assembleDebug :app:assembleValidation :app:assembleValidationAndroidTest :app:lintDebug '-PtestBuildType=validation' --no-parallel --max-workers=1
```

设备测试仅安装独立包 `com.example.foodmanager.validation` 与对应测试 APK，不覆盖原应用或读取原应用库存。安装不使用自动授权参数。

```text
adb shell am instrument -w -r -e targetDisplay 0 -e class com.example.foodmanager.ReliabilityInstrumentedTest,com.example.foodmanager.PageRecoveryInstrumentedTest com.example.foodmanager.validation.test/androidx.test.runner.AndroidJUnitRunner
```

若该设备测试停留在启动阶段，可在另一终端显式启动同一测试包的 MainActivity 使其进入前台；不得替换为原应用包名。
