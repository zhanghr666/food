# 食物管家 · 需求文档

> 版本：v1.0（对应数据库 schema v8）
> 平台：Android 原生（Kotlin + Jetpack Compose）
> 定位：**完全离线的本地食物存储管理工具**，不注册、无应用联网权限；系统云备份关闭，Android 12+ 可在换机时由系统迁移食物数据库

---

## 1. 产品目标

帮助家庭用户回答三个问题：

1. **我有什么？** —— 用最省力的方式把食物记进手机
2. **放在哪？** —— 按位置快速找到
3. **什么时候过期？** —— 在坏掉之前提醒

**核心约束**：全部能力必须在**无网络**环境下可用，数据只存在本机。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| **记录 / 条目** | 一条食物数据（名称 + 数量 + 位置 + 日期等） |
| **待入库** | 拍照/语音识别出、还没确认写入库存的**草稿** |
| **归档** | 已用完 / 已丢弃的记录，不再提醒，但可恢复 |
| **常用存放地点** | 用户维护的位置清单，供下拉选择与语音识别 |
| **常用食品** | 用户维护的食品名清单，进入语音词表与 OCR 优先匹配 |
| **别名** | 某个位置/食品的同义词（如「冰箱」的别名「冷藏」） |
| **临期** | 距保质期 ≤ 提醒天数 |
| **无保质期** | 未填生产日期与保质期，永不提醒 |

## 3. 功能需求

### 3.1 三种录入方式（底部「录入」标签）

三种方式**并列展示**，点击互斥展开；**默认展开手工录入**。
切换标签页再回来，展开状态与已填内容**都不丢失**。

#### FR-1 拍照录入

| 项 | 说明 |
|---|---|
| 输入 | 系统相机拍照，或从相册选图 |
| 识别 | ML Kit 中文文字识别，**完全离线**，模型内置于 APK |
| 解析 | 从包装文字里提取：名称、分类、数量、单位、生产日期、保质期 |
| 输出 | 进入**待入库**列表，用户核对后入库 |
| 单件/批量 | 默认**一张照片 = 一条记录**；可在设置里切换为「按行拆分」（适合拍购物小票） |
| 日期喷码 | 提供「单独拍日期」按钮：只裁取画面中上部区域、放大 3 倍并增强对比度后单独识别，用于点阵喷码 |
| 增强识别 | 整图识别 + 对比度增强图识别**取并集**，避免浅色小字被漏掉 |
| 原文留证 | 可展开「查看识别原文」，核对识别结果 |
| 提示 | 显示「识别到 N 条（单件模式/拆分模式）：名称…」 |

#### FR-2 语音录入

| 项 | 说明 |
|---|---|
| 交互 | **按住说话**（手指按下开始录音、抬起提交本轮识别） |
| 引擎 | Vosk 离线中文模型（约 65MB，首次使用解包） |
| 语法约束 | 用领域语法词表约束解码（含用户自定义位置/食品及其别名），显著降低解析错词 |
| 解析内容 | 名称、数量、单位、位置、生产/保质期、备注 |
| 口语支持 | 「牛奶两瓶放冰箱冷藏，六月一号过期」「鸡蛋两盒，三周后过期」 |
| 位置别名 | 说别名（「放冷藏」）自动归到正式名（「冰箱」） |
| 兜底 | 解析失败时提示并**切到手工录入**，把原话带进名称框 |
| 批量 | 支持「还有 / 另外 / 然后 / 、」分隔的多条记录 |

#### FR-3 手工录入

| 项 | 说明 |
|---|---|
| 字段 | 名称（必填）、分类（可选、可自定义手填）、数量、单位、存放位置、保质期至、生产日期、备注 |
| 位置 | **不预填**；可从常用地点下拉选，也可直接手填新位置 |
| 键盘 | 名称框按「下一项」跳转到数量框 |
| 保存 | 保存后清空表单、收起键盘、提示「已保存 X，可以继续录入下一条」、滚动回顶部 |
| 位置为空 | **拦下不落库**，给出橙色提醒（位置用于快速查找） |
| 入库 | 直接进库存（**不经过待入库**） |

### 3.2 待入库（草稿）

| 项 | 说明 |
|---|---|
| 来源 | 仅拍照 / 语音（手工录入不经过） |
| 卡片信息 | 序号、名称、数量、到期与剩余天数、识别字段、置信度 |
| 单条操作 | 单条入库 / 修改（就地改各字段）/ 移除 |
| 批量操作 | 全部入库 / 清空 |
| 位置为空 | 显示时省略「位置：」，不套用最近位置 |

### 3.3 首页

| 项 | 说明 |
|---|---|
| 到期概览 | 已过期 / 即将过期 / 新鲜 / 无保质期 四类计数 |
| 快捷入口 | 三个录入方式入口（拍照 / 语音 / 手工） |
| 提醒清单 | 需要尽快处理的条目，最多显示 8 条；点标题进库存 |
| 空状态 | 无记录时给出引导文案 |
| 通知跳转 | 从通知点进来时，自动切到首页并**滚动到提醒清单** |

### 3.4 库存

| 项 | 说明 |
|---|---|
| 列表 | 按状态排序：已过期 → 即将过期 → 新鲜 → 无保质期；同状态按到期日 |
| 搜索 | 覆盖名称、分类、位置、备注 |
| 位置筛选 | 按**实际用过的位置**筛选（来自记录，不是常用列表） |
| 标题 | 无筛选显示「库存（N）」；有筛选显示「库存（筛出 N）」 |
| 卡片内容 | 名称、数量、位置、到期与剩余、状态色 |
| 数量为 0 | 视为未填写，卡片不显示数量 |
| 操作 | 修改、标记已用完（**二次确认**）、删除（**二次确认**） |
| 新增 | 右下角「添加食物」进入编辑页 |

### 3.5 编辑 / 新增页

| 项 | 说明 |
|---|---|
| 入口 | 库存卡片、首页清单项、空状态按钮、通知 |
| 录入方式 | 页内同样提供拍照 / 语音 / 手工三种入口（与前次选择一致） |
| 复用 | 与「录入」页共用手工表单组件；编辑内容由 EditorViewModel 单独持有并恢复，校验读取同一份内容 |
| 位置为空 | **弹窗确认**「仍要保存」（与录入页"直接拦下"是刻意保留的差异） |
| 拍照补日期 | 拍照卡片提供「手动选保质期」直接选日期 |
| 保存 | 顶栏 ✓ 与表单按钮走同一校验路径 |
| 已有记录 | 可标记已用完、删除 |

### 3.6 提醒

| 项 | 说明 |
|---|---|
| 开关 | 系统通知提醒、首页提醒横幅，各自独立 |
| 提前天数 | 可配置（默认 3 天） |
| 提醒时刻 | 每天固定小时（默认 9 点） |
| 调度 | WorkManager 每日周期任务；支持重启后恢复，受省电策略影响，时间为近似检查时间 |
| 通知 | 两个渠道：即将过期 / 已过期；点击跳转首页提醒清单 |
| 手动检查 | 设置页提供「立即检查一次」，显示检查结果 |
| 图标 | 自带单色小图标（避免系统白块） |

### 3.7 设置

| 分组 | 项 |
|---|---|
| **提醒** | 系统通知开关、首页横幅开关、提前天数、每日提醒时间、立即检查一次 |
| **常用存放地点** | 增 / 删（最多 20 条）、**别名**编辑；删除前提示「有 N 条在库记录在用这个位置」，并说明已有记录文字不变 |
| **常用食品** | 增 / 删（最多 20 条）、别名编辑 |
| **录入偏好** | 「一张照片只识别一件商品」开关 |
| **数据与隐私** | 记录数 / 归档数 / 分类数 / 位置数统计、待入库暂存数、拍照识别模式、上次拍照解析结果、查看归档、清空全部数据、版本号 |
| **归档页** | 恢复一条（带提示）、删除（二次确认，带提示） |

## 4. 数据需求

### 4.1 存储

| 项 | 说明 |
|---|---|
| 数据库 | 本机 SQLite（Room），文件 `food_manager.db`，**当前 schema v8** |
| 语音模型 | 存 `noBackupFilesDir`（**不进系统备份**，避免 65MB 撑爆 25MB 备份配额） |
| 拍照临时图 | 存 `cache/images/`，识别完立即删除，并兜底清理超过 24 小时的残留 |
| 备份 | 关闭系统云备份；Android 12+ 仅允许设备间迁移食物数据库，旧系统不自动备份 |
| 导出/导入 | **暂不提供** |

### 4.2 表结构

| 表 | 内容 |
|---|---|
| `food_items` | 食物记录 |
| `app_settings` | 单行配置 |
| `storage_locations` | 常用存放位置（name 唯一、alias、sortOrder、createdAt） |
| `common_foods` | 常用食品（结构同上） |

**关键设计**：`food_items.location` 存**字符串**，不与 `storage_locations` 建外键。
因此**删除一个常用位置不影响已有记录的位置文字**。

### 4.3 迁移

当前 v1–v7 均通过**直接迁移至 v8**完成升级，重建设置表以兼容旧 SQLite，不吞迁移异常。以下表格保留字段演进历史，`food_items` 表未变化：

| 版本 | 变更 |
|---|---|
| v1→v2 | 加常用位置列 |
| v2→v3 | 加常用食品、上次录入方式 |
| v3→v4 | 加「一张照片一条」开关（默认开） |
| v4→v5 | 加行为归一化标记（后作废） |
| v5→v6 | 删该标记 |
| v6→v7 | 删「沿用上次位置」开关 |
| v7→v8 | **拆表**：位置/食品迁入独立表，删旧列，加初始化标记 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| **离线** | 全部功能无网络可用；不申请网络权限 |
| **隐私** | 数据不上传；拍照仅本地识别 |
| **权限** | 相机、录音、通知、开机自启（用于恢复提醒任务） |
| **兼容** | minSdk 24 / targetSdk 37；数据库升级不丢数据 |
| **性能** | 拍照识别与语音识别在后台线程；位图用完立即回收 |
| **容错** | 识别失败可切手工；增删改都有明确反馈；危险操作二次确认 |
| **可维护** | 以构建报告为准；单元测试与独立 validation 包设备测试覆盖解析、状态、保存和迁移 |

## 6. 交互一致性约定

| 约定 | 说明 |
|---|---|
| 手工表单 | 录入页与编辑页共用组件；各自仅有一份表单数据，识别、校验和保存使用同一份当前内容 |
| 位置为空 | 录入页拦下（橙色提醒）；编辑页弹窗确认——唯一刻意差异 |
| 保存反馈 | 统一走表单内状态提示 `statusMessage` / `statusIsError` |
| 危险操作 | 删除记录、清空数据、删除常用项，一律二次确认 |
| 弹出层 | 保存前先收键盘与焦点，再清表单，最后滚动回顶部 |

## 7. 明确不做（当前范围外）

| 项 | 原因 |
|---|---|
| 账号 / 云同步 | 产品定位为纯本地 |
| 导出 / 导入 | 暂不需要（已确认） |
| 多用户 / 共享 | 单机单人 |
| 条码扫描 | 依赖在线数据库，与离线定位冲突 |
| 位置拖拽排序 | 已确认暂不需要（`sortOrder` 列已预留） |
| 国际化 | 当前仅中文（文案硬编码） |

## 8. 已知限制

| # | 限制 | 影响 |
|---|---|---|
| 1 | **点阵喷码日期识别率低** | 部分包装的生产日期/保质期需手动填写（已提供「单独拍日期」与「手动选保质期」两条退路） |
| 2 | 待入库草稿与表单使用系统状态恢复 | 支持 Activity 重建与系统保存状态后的进程恢复；不承诺强制停止、卸载或未保存状态时恢复 |
| 3 | 位置/食品上限 20 条 | 过多会让离线语音词表膨胀、拖慢识别 |
| 4 | 无索引 | 记录量大后查询会变慢（当前量级无感） |
| 5 | 删除常用位置**不回填**记录 | 删掉的只是下拉选项，历史记录文字保留 |
| 6 | 日期按「当地 0 点」存储 | 跨时区修改系统时区会影响历史日期显示 |

## 9. 验收要点

| # | 场景 | 期望 |
|---|---|---|
| 1 | 手工录入不填位置就保存 | 被拦下，橙色提醒，不落库 |
| 2 | 拍照一张单件商品包装 | 待入库**只有 1 条** |
| 3 | 语音「牛奶两瓶放冰箱冷藏，六月一号过期」 | 名称/数量/位置/保质期都正确 |
| 4 | 给「冰箱」填别名「冷藏」后说「放冷藏」 | 位置归为「冰箱」 |
| 5 | 切到库存再切回录入 | 草稿与表单内容仍在 |
| 6 | 点通知 | 打开首页并滚到提醒清单 |
| 7 | 删除某个常用位置 | 提示在用条数；已有记录位置文字不变 |
| 8 | 升级安装（旧库） | 记录与设置**不丢失** |
| 9 | 开飞行模式使用全部功能 | 完全可用 |
| 10 | 连拍多张照片 | 相机缓存目录不堆积 |
