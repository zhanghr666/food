## 3. 三条录入链路（核心数据流）

### 3.1 拍照识别

```
用户拍照 / 选相册
      │
      ▼
CameraFiles.createImageFile()            ← cache/images/（FileProvider 暴露给相机）
      │
      ▼
OcrEngine.loadBitmapFromFile()           ← 最长边压到 2600，保留点阵小字
      │
      ├──────────────► 通道① 原图  ──────► ML Kit ──┐
      │                                            │
      └─► enhanceForDotMatrix()（灰度+百分位拉伸）  │
                    │                              │
                    ▼                              │
             通道② 增强图 ──► ML Kit ──────────────┤
                                                   ▼
                                     OcrEngine.mergeText()  ← 逐行去重取并集
                                                   │
                                                   ▼
                              OcrTextParser.parse(singleItemMode)
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
        单件模式：整段 = 1 条          批量模式：splitRecords 按行拆
                    │                               │
                    └───────────────┬───────────────┘
                                    ▼
                          List<FoodDraft> → ScanEntryState.drafts
                                    │
                                    ▼
                         待入库卡片 → 用户核对 → 入库
```

**两个关键设计**：
- **双通道取并集**：增强图可能让印刷体识别更差，所以**不能替换、只能合并**；合并时含日期样式的行一律保留
- **二值化只用于裁剪后的小区域**：整图二值化会把深色图案（红马卡龙）变成黑斑，反而干扰识别

**日期喷码专用通道**（应对低识别率）：

```
「单独拍日期」→ cropRegion(中上部) → upscaleAndStretch(×3) → ML Kit → 与整图结果并集
```

### 3.2 语音识别

```
按住说话（按下开始 / 抬起提交）
      │
      ▼
VoiceRecognizer.ensureModel()            ← no_backup/vosk-model-cn（首次解包 65MB）
      │                                     临时目录 → 打标记 → 整体 rename（原子）
      ▼
readGrammarWords()                       ← storage_locations + common_foods（**含别名**）
      │
      ▼
VoiceGrammar.build()  ──► 领域语法词表（指纹变化时重建）
      │
      ▼
麦克风 PCM ──► Vosk（语法约束解码）──► Partial / Result
      │
      ▼
VoiceTextParser.parse(text)
      ├─ VoicePhoneticCorrector.correct()   ← 同音字校正（用常用食品词表）
      ├─ ShelfLifeParser / DateTextParser   ← 保质期与日期
      ├─ matchCustomLocation(位置名 + 别名)  ← **返回正式名**，不是别名
      ├─ findQuantity / NumberParser        ← 中文数字
      └─ extractName(剔除位置名与别名)        ← 防止"冷藏"混进食物名
      │
      ▼
FoodDraft → 待入库；解析失败 → 切手工并把原话带进名称框
```

### 3.3 手工录入（两页共用一套状态机）

```
        ScanScreen（录入页）              EditorScreen（编辑页）
                 │                                │
                 └──────────┬─────────────────────┘
                            ▼
                   ManualEntryState
        ┌───────────────────────────────────────────┐
        │ item / resetToken / status / statusIsError │
        │ confirmLocationWhenBlank ← 唯一差异开关     │
        │ update() / prefillName() / resetAfterSave()│
        │ requestLocationConfirm() / canSaveWithout… │
        └───────────────────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
     位置为空 → 拦下（橙色）      位置为空 → 弹窗确认
              │                           │
              └─────────────┬─────────────┘
                            ▼
                    保存成功
              ┌─────────────┴─────────────┐
              ▼                           ▼
   清空表单+提示+滚回顶部          关闭页面回列表
```

**为什么抽出来**：两页原先各写一套，导致"位置为空"处理不同、"保存后"行为不同。抽成状态机后差异只剩一个开关，无法再各自漂移。

## 4. 数据模型与关系

```
┌──────────────────────────┐
│ storage_locations        │        ┌──────────────────────────┐
│ id (PK, auto)            │        │ common_foods             │
│ name   UQ                │        │ id (PK, auto)            │
│ alias  「冷藏|冷藏室」     │        │ name   UQ                │
│ sortOrder                │        │ alias                    │
│ createdAt                │        │ sortOrder / createdAt     │
└──────────────────────────┘        └──────────────────────────┘
        │                                      │
        │ 供下拉 / 语音词表 / 别名归一            │ 供语音词表 / 同音字校正 / OCR 优先匹配
        │                                      │
        └───────────────┬──────────────────────┘
                        │  （**不建外键**）
                        ▼
┌──────────────────────────────────────┐        ┌────────────────────────┐
│ food_items                           │        │ app_settings（单行）    │
│ id (PK, auto)                        │        │ id = 1                 │
│ name / category / quantity / unit    │        │ warnDays               │
│ purchaseDate / productionDate?       │        │ notifyEnabled          │
│ expiryDate?                          │        │ homeBannerEnabled      │
│ location  ← **字符串，非外键**         │        │ notifyHour             │
│ note / source / archived             │        │ ocrSingleItem          │
│ createdAt / updatedAt                │        │ lastLocation / lastUnit│
└──────────────────────────────────────┘        │ lastEntryMode          │
                                                │ locationsInitialized   │
                                                └────────────────────────┘
```

**`location` 为什么是字符串**：用户手填的位置、语音识别出的非标准位置都会落在记录上，改外键需要回填历史数据且匹配不上的情况无法兜底。
**代价（已接受）**：删除一个常用位置不会影响已有记录的位置文字——界面上会明确提示这一点。

**时间字段语义**：所有日期都是「当地当日 0 点」的 epoch 毫秒，因此算天数差无需关心时分秒。

## 5. 状态管理

| 状态 | 存放位置 | 生命周期 | 抗进程回收 |
|---|---|---|---|
| 当前标签页 `tab` | `FoodsApp` · `rememberSaveable` | 整个 App | ✅ |
| 全屏子页 `fullScreen` | `FoodsApp` · `rememberSaveable` + `Saver` | 整个 App | ✅ |
| 上次录入方式 `entryMode` | `FoodsApp` · `rememberSaveable` | 整个 App | ✅ |
| **待入库草稿** | `ScanEntryState`（`FoodsApp` 层 `remember`） | 整个 App | ❌ |
| **手工表单内容** | `ManualEntryState`（同上） | 整个 App | ❌ |
| 编辑中条目 | `EditorViewModel` | 编辑页 | ❌ |
| 设置 / 列表 / 统计 | `FoodViewModel`（Flow） | 整个 App | ✅（源在数据库） |

**关键取舍**：草稿与表单挂在 `FoodsApp` 层而不是 `ScanScreen` 内，所以**切标签页不丢**；但**进程被回收仍会丢**（这是"持久化到磁盘"的范畴，当前明确不做）。
`fullScreen` 用自定义 `Saver` 编码成 `Long`（`-1` 无 / `0` 归档 / 正数 编辑 id），使编辑页在系统回收后能恢复。

## 6. 导航设计

**不使用 NavHost**，改用两个状态量：

```kotlin
var tab by rememberSaveable { mutableIntStateOf(0) }          // 0首页 1库存 2录入 3设置
var fullScreen by rememberSaveable(stateSaver = FullScreenSaver) {
    mutableStateOf<FullScreen?>(null)                          // Archived | Editor(itemId)
}
```

```
                    FoodsApp
                       │
        ┌──────────────┴──────────────┐
        ▼                             ▼
   fullScreen == null           fullScreen != null
        │                             │
        ▼                    ┌────────┴────────┐
   底部 4 标签页             ▼                 ▼
   （首页/库存/录入/设置）  Archived 页      Editor(itemId)
```

**为什么不用 NavHost**：页面只有 6 个、层级只有 2 层、没有深链接需求。用手写状态量换来：可保存恢复、无路由库依赖、参数传递类型安全。

## 7. 离线能力与第三方依赖

| 能力 | 实现 | 模型位置 | 体积 |
|---|---|---|---|
| 中文文字识别 | ML Kit `text-recognition-chinese:16.0.1` | 随 APK（AAR 内置） | — |
| 中文语音识别 | Vosk `vosk-android:0.3.75` + 内置模型 | `no_backup/vosk-model-cn` | 65.1 MB |
| 本地存储 | Room 2.7.2 + SQLite | `databases/food_manager.db` | — |
| 定时提醒 | WorkManager（每日周期任务） | — | — |

**权限**：相机、录音、通知、开机自启。**没有网络权限**。

**备份策略**（重要）：
```
系统自动备份配额 = 25 MB / 应用
  food_manager.db         ✅ 在备份范围内（KB 级）
  vosk-model-cn（65MB）    ❌ 放 noBackupFilesDir，天然排除
  cache/images            ❌ cache 目录本就不备份
```
模型若放在 `filesDir` 会**撑爆配额导致整包备份失败且无提示**，这是当前架构里最关键的存储决策之一。

## 8. 数据库演进

```
v1 ──► v2 ──► v3 ──► v4 ──► v5 ──► v6 ──► v7 ──► v8
     +位置   +食品   +单件   +归一   -归一   -沿用  拆表
             +模式   开关    标记    标记   位置    (2 张新表)
                     (默认1)
```

| 原则 | 说明 |
|---|---|
| **无破坏式迁移** | 不用 `fallbackToDestructiveMigration`，升级不丢数据 |
| **`food_items` 从未变化** | 所有变更只涉及 `app_settings` 与新表，风险面小 |
| **删除列要兼容老系统** | v1–v7 直接迁移到 v8，按实际列复制数据并重建设置表；不使用 DROP COLUMN，不忽略异常 |
| **schema 导出** | `exportSchema = true`，`app/schemas/` 保留各版本 JSON 供 Room 校验 |

## 10. 架构决策记录（ADR 摘要）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 1 | 单 `FoodRepository` 作为唯一数据出入口 | 数据流向可追踪，Context 传递统一 | 仓库类偏大（26 方法） |
| 2 | `FoodItem.location` 用字符串而非外键 | 免回填历史、容忍非标准位置 | 删除位置不影响记录，需界面提示说明 |
| 3 | 常用位置/食品**拆独立表**（v8） | 字符串无法表达项属性（别名、排序） | 多一次迁移与一次读写重构 |
| 4 | 手工表单抽成 `ManualEntryState` | 消除两页行为漂移 | 多一层间接 |
| 5 | 语音模型放 `noBackupFilesDir` | 避免撑爆 25MB 备份配额 | 换机后首次语音需重新解包 |
| 6 | 不用 NavHost | 页面少、层级浅 | 深链接需自行扩展 |
| 7 | OCR 双通道取并集 | 兼顾印刷体与点阵喷码 | 每次识别多一遍耗时 |
| 8 | 界面状态挂 `FoodsApp` 层 | 切标签页不丢草稿 | 进程回收仍会丢 |
