# 地点、共用提醒与查找实施计划

目标：执行用户指定的地点、提醒、查找（报告表格中查找为第 8 项），保留完全离线、自由地点和现有库存。

1. 地点操作放在 ItemRepository 事务中：重命名/合并同时更新食品、物品、常用模板、最近位置；旧名称作为显式别名保留。用户确认受影响记录数；常用置顶不改变位置含义。
2. 数据库 v2→v3 增加共用单次提醒表，食品日期自动同步，物品详情可设置日期和说明。已处理与稍后提醒不修改库存数量、归档或食品过期日期。
3. 共享提醒清单按食品/物品筛选，展示待处理/已处理、未来日期、到期状态；归档不通知，删除级联清理。继续用每日后台检查，不承诺整点送达。
4. 查找规则独立成核心逻辑：全半角/空格归一、多个关键词、名称优先、位置显式别名；全局查找可看食品和物品。别名歧义不强制归一，不删除地点中的方位词。
5. 本地测试覆盖搜索、歧义、提醒日期/延后/处理/归档和地点事务 SQL；构建、生成 schema 并验证迁移，原应用覆盖安装。真机自动点击限制保持尊重，不安装验证应用。

第一版仅单次物品提醒，支持在详情设置，不增加必填字段；不实现周期任务和跨设备同步。

## 验证结果

- 离线构建通过；本地测试共 200 项，失败 0 项。
- 新增 8 项用例覆盖组合条件、全半角型号、名称优先、诊断原文隔离、显式地点别名及歧义、方位保留、提醒提前量、处理/归档抑制和延后日期。
- SQLite 内存验证 v2→v3 的实际迁移 SQL 与 schema 一致；食品提醒自动生成，库存与照片保持不变，删除记录级联删除提醒。
- 原应用覆盖安装成功，真机提醒清单显示 27 项历史食品日期提醒；启动日志未发现数据库或崩溃错误。
- 本轮未自动点击手机上的地点合并、设置提醒等操作，也未修改用户库存；上述完整交互还需用户试用。测试源继续排除在 Git 外。
- 物品提醒在详情中设置，当前每条记录一项单次日期提醒；后台每日检查受系统调度影响。
