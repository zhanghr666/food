# Reliability Implementation Plan

**Goal:** 修复页面恢复、保存确认、日期刷新、历史数据库升级和离线权限承诺。

**Architecture:** 保留当前单模块结构。编辑内容只有一个状态源；草稿和编辑内容纳入系统状态恢复；写入完成才反馈成功；统一日期流；历史数据库直接迁移到规范 v8 表结构。

**Tech Stack:** Kotlin、Compose、SavedStateHandle、Room、WorkManager。

1. 数据库：检查历史实际列，v1–v7 直接迁移 v8，重建设置表替代 DROP COLUMN；迁移失败不吞异常。测试字段、默认值、特殊字符、空常用项和旧版本 schema 偏差。
2. 时间：Repository 日期流参与统计/提醒计算，前台监听日期、时间、时区及恢复事件；页面使用同一日期。修复关闭横幅时的错误无临期提示。
3. 状态：导航用带类型编码；同一个编辑 ViewModel 按会话重置，SavedStateHandle 保存表单；ScanEntryState 使用 Saver，恢复草稿 id 时避免碰撞；系统返回与界面返回行为一致。
4. 保存：单次提交门禁、失败保留内容、成功再清表单；编辑加载/保存错误可见；校验读取唯一编辑内容；批量保存只移除已提交快照。
5. 权限：移除合并后的 INTERNET；仅在语音使用时申请录音；通知设置显示实际系统状态；录音前重新检查权限；禁用云备份并明确设备迁移范围。
6. 提醒：处理通知导航状态，删除/归档后刷新并逐类取消旧通知；表述为约定时检查而非整点送达保证。
7. 验证：新增有意义的状态、保存失败、时间、数据库迁移测试；运行单元测试、Lint、Debug 构建和 Release Manifest 检查。若无测试设备则保留设备测试并说明边界。

取舍：不重写导航栈、不拆 Gradle 模块；系统恢复保证旋转与系统回收场景，不将强制停止/卸载后恢复承诺为已支持。保留现有位置留空规则，不扩展本次为视觉改版。
