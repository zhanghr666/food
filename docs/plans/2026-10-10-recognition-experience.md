# 食物管家识别与纠错体验 Implementation Plan

**Goal:** 恢复原应用身份，解决真实样本中的同音名称、位置漏填、歧义提示隐藏和保存错误不可见问题。

**Architecture:** 保持现有离线引擎和录入状态，新增字段候选状态。名称候选由解析产生，确认通过原人工编辑路径完成，保留人工保护和草稿恢复。

**Tech Stack:** Kotlin、Compose、Room、Vosk、ML Kit。

1. 恢复 applicationId=com.example.foodmanager、名称“食物管家”，提高版本号以支持覆盖更新。沿用本次重构数据库，不清除数据库或实施破坏性迁移；旧数据库兼容仍不在本轮范围内。
2. 将同音名称候选作为结构化字段状态，不藏在备注中；有歧义的字段不计入已提取项数，保存前需点选候选或保留原文。人工编辑清除候选且不可被后续识别覆盖。
3. 补充客厅等常见位置，支持明确“放在/在…放着”的未配置位置；避免位置和数字混进食品名称。
4. 名称卡片就地纠错、完整显示日期、直接展示照片日期候选；保存错误靠近保存按钮，批量保存定位到第一条有问题的记录。

本轮不宣称更换模型或已达到真实语音正确识别四项的目标。

## 识别不确定性、字段混淆与纠错成本的统一处理

用户实说“有三个石榴放在储藏室里还有3天过期”，转写为“有 三个月 十六 放在 储藏室 里 还有 十 天 过期”。该样本用于回归，不给整句话写固定替换。本轮不把十天硬改为三天，不宣称更换引擎后达到准确率目标。

1. 转写不确定性：VoiceRecognizer.kt 开启最多三条转写，VoiceTranscript.kt 在语音端点间保留有界的完整候选路径，不丢弃前后半句。保留第一条转写作原文，不按“填得多”重排为真值。
2. 字段冲突：新增 RecognitionAlternatives.kt 比较候选的名称、数量、单位、地点和日期。原文为空但其他候选有值时只作为待确认建议，现有值有差异时保持现有值并展示候选；等价的中文和数字表达不构成冲突。
3. 语义混淆：VoicePhoneticCorrector.kt 对数量槽内多出时间单位且名称有唯一同音食品候选的情况输出数量、单位和名称建议；真正的时长、时间角色及自定义数字食品名不推成库存。SmartTextParser.kt 将恢复值记为建议，明显结构异常时日期额外要求核对。只用语义提出候选，不宣称从文字还原了真实音频。
4. 统一核对：EntryDraft.kt / EntryViewModel.kt / EntryFields.kt / EntryScreen.kt 共用字段候选和确认状态，已填入的不确定值不算已正确识别，也不能直接保存。数量与名称一致时可以一并接受，人工输入名称不会自动确认其他字段；日期单独确认或改成快捷日期。人工字段和用户清空继续受保护，合并到已有相同值也不能丢失待确认状态。
5. 分类回归：实际错误文本、其他食品和数量、正确句、真实月数、数字食品名、备选日期数量地点、等价表达、人工保护、端点组合和输出格式分别覆盖。手机核对候选确认后数量单位和分类同步、日期仍阻止保存、手动修改日期解除确认。

6. 提醒生命周期：字段警告独立于全局引擎提示，语音、包装文字、照片数量和再次识别的冲突提示均关联具体字段；用户修正或确认对应字段后隐藏旧警告，保留其他未解决字段的提示。日期候选展示具体日期和距离今天的天数。

Vosk 输出格式依据[官方 Java 接口](https://github.com/alphacep/vosk-api/blob/master/java/lib/src/main/java/org/vosk/Recognizer.java)。多候选数量的作用为保留不确定性，不代表模型正确率提升；真实音频仍须样本验收。

执行结果：157 项 JVM 测试通过，Debug 与 Android 测试包构建通过，lint 为 0 错误、22 警告和 1 提示。两项针对检查通过：真实麦克风的按住录音与松手结束、候选与日期完整核对流程。后者包含新旧语音 JSON 格式解析、组合候选同步数量单位及分类、日期尚未确认时阻止保存、修改日期后解除确认并隐藏旧字段提醒；最终截图已核对。一次初始脚本使用未合并语义树读取按钮文字失败，调整后通过；最终页面复查曾被通知面板遮挡，关闭后重跑通过，不记为产品逻辑成功或崩溃。新版已覆盖安装，使用内存数据完成检查，临时组件已移除并恢复正常应用。没有真实音频样本准确率测量，不宣称语音听写准确率已达标。
