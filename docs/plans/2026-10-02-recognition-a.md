# 识别准确性方案 A 执行计划

**Goal:** 保留离线模型，修复语音结果、纠错、语义解析和识别填表，保护用户已确认内容。

**Architecture:** 原始文字不被识别器改写；解析层统一日期和数量语义；填入层按字段来源保护手动修改。无需数据库升级。方案 B 的取景、裁剪、候选交互留待下一阶段。

**Tech Stack:** Kotlin、Vosk、ML Kit、Compose、JUnit、Android instrumentation。

## 1. 语音结果与生命周期
- VoiceRecognizer 收集分段 result、partial 和 final；独立 VoiceTranscript 做文本聚合测试。
- 收尾停止麦克风、等待采集退出后再取 final/关闭识别器；快速松手、重复松手、离开页面与新会话隔离。
- 每次开始前刷新语法词表；原始识别文字送入解析层，不在识别器中纠错。

## 2. 语义与纠错
- 纠错限定食品/位置/时间上下文；真实词语保留，模糊食品只给备注建议；食品别名按正式名映射。
- 日期仅在明确生产/购买/到期标签附近提取；冲突留空；保质期仅从明确生产日期推算。
- 数量区分库存与规格/营养，保留箱、盒、包等包装单位；储存条件进入备注。
- 回归测试覆盖原有典型句式和误识别反例；旧测试若断言了已确认错误语义，改为新验收行为并记录。

## 3. 字段保护
- 共用识别草稿合并策略；记录手动修改的字段（包括用户主动清空的字段），恢复状态时保留保护。
- 缺失数量、单位、购买日期不覆盖现值；日期补填只应用日期。

## 4. 验证
- JVM 单元测试、独立 validation 包构建与 lint。
- 若设备可用，独立验证包执行语音/表单相关测试；不替换正式包，不读取正式库存。
- 验收文档区分逻辑回归与真实照片/音频准确率，不虚报模型能力提升。

用户已选择方案 A 并授权执行，在现有工作区保留前序未提交修改；不创建缺少这些修改的新工作树，不对前序修改整体提交。
