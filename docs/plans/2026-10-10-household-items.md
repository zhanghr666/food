# 家庭物品管理第一、二阶段实施计划

**目标：** 食品和物品分别录入，共用位置查询；照片作为现场记录，可多张保存和独立放大查看。保持离线和现有应用身份，保留现有食品。

**架构：** managed_items 保存共同信息，food_details 保存食品专属日期，photo_attachments 保存照片顺序。food_items 只读视图兼容现有食品查询；食品写入统一通过事务写入共同表和明细。数据库从 v1 自动迁移到 v2。

**技术：** Kotlin、Compose、Room、本地 Vosk、应用内部文件。物品解析不使用食品纠音词表，不添加服务器或网络权限。

1. 建立共同记录、食品明细、附件表及无损迁移，保留食品 API。
2. 建立通用物品解析和独立草稿；名称、位置必填，数量默认 1、单位默认件，其他可空。人工修改保护，原文可重解析。
3. 建立照片导入、内部存储、持久化草稿、事务保存。照片导入与食品拍照识别区分。
4. 建立物品主页、详情、多图查看，接入食品附件与详情。
5. 改造导航为食品、物品、位置、设置；位置支持类型筛选和三种排序，保留常用位置维护。
6. 离线构建、检查数据库结构和变更，纳入非测试 Git 文件；如指定手机连接可用则覆盖更新。

**验证约束：** 初始要求由用户自行测试；2026-10-10 用户重新授权真机测试，并明确不备份、直接覆盖更新。物品通知/提醒中心属于第三阶段，本轮不实现；食品提醒继续使用食品专属日期。不宣称已测得通用物品语音识别准确率。

**验收场景：** “三节五号电池放在客厅抽屉里”保留型号、提取数量单位位置；未知物品名称不纠成食品；手工位置不被重新解析覆盖；多张现场照片保存后重启仍可查看；食品照片识别仍可用，现场照片不自动解析。

## 实施结果

- 已完成食品、物品独立入口和独立持久化草稿，共用本地库存基础与位置查询。应用名称与包名保持原样，未增加网络权限。
- 物品支持语音、文字和直接编辑；仅名称、位置必填，数量默认 1、单位默认件、分类默认未分类。手工修正受保护，重新整理原文不会覆盖。
- 食品和物品均支持多张现场照片，相机和相册导入、移除、排序、设置封面；照片复制至内部目录，不依赖相册临时授权。列表使用无图风格，详情提供缩略图及全屏滑动、双击和双指缩放。
- 库存与附件事务提交，重复提交新草稿不覆盖已入库后另行编辑的内容；未加载成功的旧附件会阻止保存并提供重试。
- 位置页展示食品和物品统计，支持类型筛选、搜索及从多到少、从少到多、不排序。位置常用选项移除不删除库存。

## 验证记录

- 离线构建成功：应用安装包、真机验证包均已生成。
- 本地回归：179 项，失败 0、错误 0。包含任意物品名称、型号数字与数量区分、自由位置、人工修改保护、默认值与可选字段等解析检查。
- 小米真机：3 项全部通过。覆盖 v1→v2 食品字段及编号保留、照片事务与顺序、重复提交保护、缺失照片回滚、持久化草稿；物品详情→多图全屏切换→编辑保存→共享位置查询；检查前后食品记录编号集合保持一致。
- 已覆盖安装原应用，没有备份、卸载原应用或清空原应用数据。验证使用专属临时记录并清理，测试源代码仍按用户要求排除在 Git 外。
- 真实语音名称准确率、相机/相册的不同系统交互和全屏缩放的手感仍需日常使用反馈。通用物品提醒不在本阶段提供。

## 物品首页统计栏统一

- 物品页采用与食物页一致的日期说明、浅绿色三栏统计卡及录入按钮间距。
- 在库显示未归档物品记录数；地点显示这些记录使用的非空、去除首尾空格后去重的位置数。统计不受搜索、位置筛选和归档页切换影响。
- 点击在库清除筛选并返回库存；点击地点打开在库物品的位置选择页。
- 通用物品提醒尚未接入，第三栏显示“— / 提醒 · 待开放”，不生成虚假的提醒数量。
